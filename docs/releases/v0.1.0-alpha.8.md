# PitchTrace v0.1.0-alpha.8

First end-to-end human-reviewed PitchTrace alpha

> **Pre-release. Not production-ready.** The runtime is verified end to end, but
> no production deployment has been performed and `npm run pilot:check`
> deliberately reports `production_ready: false`.

## What PitchTrace does

PitchTrace audits a small, robots-aware sample of a company website, records
reproducible findings and screenshots, calculates a deterministic opportunity
score and builds outreach drafts only from linked evidence. A person reviews
every draft; approval produces a `.eml` file that the operator can send
manually. **PitchTrace never sends email.**

## Highlights

- Fastify analyzer API with a PostgreSQL job queue and idempotent migrations.
- Robots-aware crawler of at most five pages with mobile Playwright rendering
  and screenshots.
- 28 finding codes, LCP/TTFB/page-weight measurements and deterministic
  `scoring.v1` opportunity scoring.
- CSV import of up to 50 companies with per-row result codes.
- Evidence-linked drafts validated against rules V1–V16, a human approval
  gate and `.eml` export.
- n8n 2.39.10 campaign workflow with human approval, a status-aware retry
  sub-workflow and short-lived artifact preview tokens.
- Backup/restore automation, a pilot readiness check, CI, Docker smoke and
  real n8n runtime tests.

Full list: [CHANGELOG.md](https://github.com/mratsag/pitchtrace/blob/v0.1.0-alpha.8/CHANGELOG.md).

## End-to-end workflow

```
CSV import
→ company validation
→ human-approved audit start
→ website audit
→ evidence-linked findings
→ score
→ validated draft
→ human review
→ .eml export
```

- No email is sent automatically. There is no SMTP, Gmail, Outlook, Resend or
  SendGrid integration.
- Approval only produces a `.eml` file.
- There is no real AI/LLM integration yet. Draft generation is deterministic.
- Every factual outreach claim is linked to a recorded finding; drafts that
  fail validation cannot be approved.

## Security model

- Only HTTP/HTTPS targets. Private, loopback, link-local, reserved and metadata
  IPv4/IPv6 addresses (including IPv4-mapped IPv6, NAT64 and 6to4) are
  rejected.
- Every redirect hop and every browser subresource goes through SSRF
  validation; connections are pinned to the validated IP while Host and TLS SNI
  are preserved, mitigating DNS rebinding.
- WebSockets and service workers are blocked; popups and downloads are closed
  or cancelled.
- Artifact path traversal and CSV formula injection are rejected.
- Artifact previews use HMAC-signed tokens scoped to one artifact with a short
  expiry; the analyzer API key never reaches the browser.
- Workflow exports contain no secrets or credential data.
- Analyzer calls from n8n fail closed with sanitized errors; `409 SUPPRESSED`
  is an explicit business outcome and suppression is re-checked at export.
- n8n and the analyzer use separate databases and credentials.

Application controls do not replace a host/cloud egress firewall. See
[docs/security-notes.md](https://github.com/mratsag/pitchtrace/blob/v0.1.0-alpha.8/docs/security-notes.md).

## Responsible-use boundaries

PitchTrace is not a spam tool. It is meant for small, deliberate,
human-reviewed outreach. Operators are responsible for robots directives,
privacy and marketing laws, suppression requests and consent requirements. See
[docs/responsible-use.md](https://github.com/mratsag/pitchtrace/blob/v0.1.0-alpha.8/docs/responsible-use.md).

n8n is not redistributed. Hosted n8n, SaaS, embedded or OEM use requires a
separate review of n8n's current license terms; see
[docs/licensing.md](https://github.com/mratsag/pitchtrace/blob/v0.1.0-alpha.8/docs/licensing.md).

## Known limitations

- No real LLM/OpenAI integration; drafts are deterministic.
- No automatic email sending and no reply tracking.
- No production deployment has been performed.
- The host/cloud egress firewall must be enforced in the target environment.
- The n8n editor access policy must be decided in the target environment.
- The external task-runner staging decision is pending
  ([ADR](https://github.com/mratsag/pitchtrace/blob/v0.1.0-alpha.8/docs/decisions/adr-task-runner.md)).
- CLS is experimental and excluded from outreach claims and scoring.
- Score thresholds are not yet calibrated with real pilot data.

## Upgrade/install notes

- Install with Docker Compose as described in the
  [README](https://github.com/mratsag/pitchtrace/blob/v0.1.0-alpha.8/README.md#installation) and
  [docs/installation.md](https://github.com/mratsag/pitchtrace/blob/v0.1.0-alpha.8/docs/installation.md). Installation commands are
  unchanged.
- Migrations are idempotent and run in order; existing data is kept. Back up
  first as described in [docs/operations/upgrade.md](https://github.com/mratsag/pitchtrace/blob/v0.1.0-alpha.8/docs/operations/upgrade.md).
- The analyzer reports `0.1.0-alpha.8` unless `ANALYZER_VERSION` is overridden.
- The pinned n8n image remains `docker.n8n.io/n8nio/n8n:2.39.10`.
- The crawler User-Agent remains
  `PitchTraceBot/0.1 (+https://github.com/mratsag/pitchtrace)`.

## Production readiness warning

This alpha is **not production-ready**. Before any public deployment you need:

- HTTPS through an authenticated reverse proxy;
- a verified host/cloud egress firewall;
- a declared n8n editor access policy;
- a successful restore drill in the target environment;
- the external task-runner staging decision.

See [deploy/README.md](https://github.com/mratsag/pitchtrace/blob/v0.1.0-alpha.8/deploy/README.md) and
[docs/pilot-guide.md](https://github.com/mratsag/pitchtrace/blob/v0.1.0-alpha.8/docs/pilot-guide.md).
