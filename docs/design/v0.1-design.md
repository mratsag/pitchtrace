# PitchTrace — v0.1 Tasarım Dokümanı (rev. 2)

Durum: VS, F3, F4, F5 ve F6 tamamlandı · Tarih: 2026-09-22 · Kapsam: v0.1 (MVP)

Revizyon 2 değişiklikleri: SSRF/crawler güvenlik sınırları, kampanya seviyesinde
audit orkestrasyonu, tek process worker modeli, `UNIQUE(campaign_id, domain)`,
URL alanlarının ayrıştırılması, suppression kurallarının düzeltilmesi, finding
kataloğunun daraltılması, artifact tabanlı screenshot erişimi.

Bu doküman implementasyondan önceki sözleşmedir. v0.1 kapsamı dışındaki hiçbir şey
(dashboard, otomatik gönderim, IMAP, reply parsing, multi-tenant, kullanıcı
yönetimi) bu belgede yer almaz ve implementasyonda da yer almaz.

---

## 0. Ürün tanımı

Bir kampanya için verilen firma listesindeki web sitelerini robots-uyumlu ve
sınırlı biçimde analiz eder, ölçülebilir teknik/mobil bulgular üretir, bu
bulgulara **kanıt bağlı** bir e-posta taslağı hazırlar ve taslağı insan
onayından geçirip dışa aktarır. **Gönderim yapmaz.**

Ayırt edici özellik: **Evidence-Linked Outreach** — taslaktaki her kesin iddia,
veritabanındaki gerçek bir bulgu kaydına bağlı olmak zorundadır; bağlanamayan
taslak reddedilir.

## 1. Sistem mimarisi

### 1.1 Bileşenler

| Bileşen | Teknoloji | Sorumluluk |
|---|---|---|
| `n8n` | n8n resmi image (repo'ya kopyalanmaz) | Orkestrasyon, LLM çağrısı, insan onay formu, zamanlama |
| `postgres` | PostgreSQL 16 | Tek veritabanı; `n8n` ve `pitchtrace` şemaları |
| `analyzer` | TypeScript (Node 24) + Fastify + Playwright | HTTP API **ve** worker döngüleri — tek process |
| artifact volume | Host bind mount | Screenshot ve export dosyaları |

Redis yok. Kuyruk PostgreSQL üzerinde `FOR UPDATE SKIP LOCKED`.

### 1.2 Process modeli (rev. 2)

Container içinde **tek Node process** çalışır. Ayrı bir process manager,
supervisor veya ikinci `node` süreci yoktur.

```
node dist/src/index.js
  ├── Fastify HTTP server            (port 8080, internal network)
  └── N adet async worker loop       (N = AUDIT_CONCURRENCY, hard ceiling 2)
      └── her loop: claim → audit → commit → tekrar
  └── stale-lock sweeper             (60 sn'de bir)
```

**Graceful shutdown (SIGTERM/SIGINT):**
1. HTTP server yeni bağlantı kabul etmeyi bırakır (`fastify.close()`).
2. Worker'lara `stopping` bayrağı set edilir → **yeni iş alınmaz**.
3. Çalışmakta olan audit'lerin bitmesi beklenir (`SHUTDOWN_GRACE_MS`, varsayılan 30 sn).
4. Süre aşılırsa çalışan audit'ler `failed`/`SHUTDOWN` ile kapatılır ve
   Chromium süreçleri kapatılır.
5. PostgreSQL pool kapatılır, process çıkar.

İleride aynı image `ROLE=api` / `ROLE=worker` env'i ile iki container'a
bölünebilir; v0.1'de gerekmez ve yapılmaz.

### 1.3 Sorumluluk sınırı

```
n8n       → ne zaman, hangi sırayla, kim onaylıyor + LLM çağrısı
analyzer  → veriye dokunan her şey: crawl, finding, score, validasyon, export
postgres  → tek doğruluk kaynağı
```

LLM'i n8n çağırır, doğrulamayı analyzer yapar. Gerekçe: model seçimi kullanıcının
tercihidir; validator ise DB erişimi gerektirir ve atlanamaz olmalıdır.

### 1.4 Uçtan uca akış

```
CSV (≤50 firma)
  → [n8n 01] POST /campaigns/{id}/companies:import
  → [n8n 02] POST /campaigns/{id}/audits           → 202 {enqueued}
             GET  /campaigns/{id}/audit-progress   → finished:true olana kadar
  → [n8n 03] GET /drafts/context?company_id
             → LLM (structured output) → POST /drafts → validator
  → [n8n 04] Form: insan inceler (+ screenshot binary) → POST /drafts/{id}/approval
             → GET /drafts/{id}/export?format=eml   (suppression 2. kontrol)
  → [n8n 05] Form: manuel durum → POST /outreach
```

## 2. Security boundaries

Bu bölüm normatiftir. Buradaki her kuralın pozitif **ve** negatif testi olmak
zorundadır; test yoksa kural uygulanmamış sayılır.

### 2.1 Tehdit modeli

Analyzer, **dışarıdan verilen** (CSV, API) URL'leri açar ve Docker internal
network'te DB ve n8n ile aynı ağdadır. Birincil tehdit **SSRF**: saldırganın
kontrolündeki bir domain'in iç servislere, cloud metadata uçlarına veya
loopback'e yönlendirilmesi.

### 2.2 URL ve protokol kabulü

- Yalnızca `http:` ve `https:` kabul edilir.
- `file:`, `ftp:`, `data:`, `javascript:`, `blob:`, `ws:`, `wss:`, `gopher:`,
  `chrome:`, `about:` ve diğer tüm şemalar reddedilir (`SCHEME_BLOCKED`).
- URL içinde kimlik bilgisi (`https://user:pass@host`) reddedilir
  (`CREDENTIALS_IN_URL`).
- Hostname blocklist: `localhost`, `*.localhost`, `*.local`, `*.internal`,
  `*.home.arpa`, `metadata.google.internal`, `metadata.goog`.

### 2.3 IP aralığı engelleri

Hostname bir IP literal ise doğrudan, değilse **DNS ile çözülür ve dönen
adreslerin tamamı** doğrulanır. Bir tanesi bile engelli aralıktaysa istek
reddedilir (`PRIVATE_ADDRESS`).

IPv4 engelli aralıklar: `0.0.0.0/8`, `10.0.0.0/8`, `100.64.0.0/10`,
`127.0.0.0/8`, `169.254.0.0/16` (**cloud metadata `169.254.169.254` dahil**),
`172.16.0.0/12`, `192.0.0.0/24`, `192.0.2.0/24`, `192.88.99.0/24`,
`192.168.0.0/16`, `198.18.0.0/15`, `198.51.100.0/24`, `203.0.113.0/24`,
`224.0.0.0/4`, `240.0.0.0/4` (`255.255.255.255` dahil).

IPv6 engelli aralıklar: `::`, `::1`, `fc00::/7`, `fe80::/10`, `ff00::/8`,
`100::/64`, `2001::/32` (Teredo), `2001:db8::/32`.
Gömülü IPv4 taşıyan biçimler açılır ve IPv4 kuralları tekrar uygulanır:
`::ffff:0:0/96` (IPv4-mapped), `64:ff9b::/96` (NAT64), `2002::/16` (6to4).

`SSRF_ALLOW_LOOPBACK=true` **yalnızca test içindir**: sadece `127.0.0.0/8` ve
`::1` serbest bırakılır; link-local, metadata, private ve reserved aralıklar
bu bayrakla dahi açılmaz. Üretim konfigürasyonunda kapalıdır.

### 2.4 Redirect ve DNS rebinding

- Başlangıç URL'sinde doğrulama **yeterli değildir**. Doğrulama şu noktaların
  hepsinde tekrarlanır:
  1. Audit başlamadan giriş URL'si,
  2. `robots.txt` isteğinin her redirect hop'u,
  3. Tarayıcıdaki **her** HTTP/HTTPS isteği (ana çerçeve + alt kaynak),
  4. Her redirect hop'u.
- Maksimum redirect: `MAX_REDIRECTS = 5`. Aşılırsa `TOO_MANY_REDIRECTS`.
- **DNS rebinding:** her URL yeniden çözülür ve bütün IP sonuçları doğrulanır.
  HTTP bağlantısı doğrulanmış IP'ye sabitlenirken orijinal Host ve TLS SNI
  korunur; Chromium'a yalnızca doğrulanmış nihai cevap verilir.
- CSS, JavaScript, görsel, font, iframe ve fetch/XHR aynı mekanizmadan geçer.
  WebSocket ve service worker v0.1'de engellidir.

### 2.5 Boyut ve süre limitleri

| Limit | Değer | Aşılırsa |
|---|---|---|
| Navigation timeout | 20 sn | `TIMEOUT` |
| Audit toplam süresi | 90 sn | `TIMEOUT` |
| `robots.txt` boyutu | 512 KB | kesilir, kalan yok sayılır |
| HTML gövde | 3 MB | `RESPONSE_TOO_LARGE` |
| Tek asset | 5 MB | istek abort edilir |
| Audit toplam transfer | 10 MB | sayfa kapatılır, `RESPONSE_TOO_LARGE` |
| Domain başına istek hızı | ≤ 1 istek/sn | dahili token bucket ile beklenir |
| Firma başına sayfa | ≤ 5 (hard ceiling) | kullanıcı yalnızca düşürebilir |

### 2.6 Chromium izolasyonu

- Container `pwuser` (non-root, uid 1000) ile çalışır.
- `acceptDownloads: false`; `page.on('download')` → `cancel()`.
- `page.on('dialog')` → `dismiss()` (alert/confirm/prompt/beforeunload kilitlenmesi yok).
- `context.on('page')` → yeni popup'lar anında `close()`.
- `serviceWorkers: 'block'`.
- Chromium'a geçilen argümanlar: `--disable-dev-shm-usage`, `--disable-gpu`,
  `--no-first-run`, `--no-default-browser-check`, `--disable-extensions`,
  `--host-resolver-rules=...`.
- **Kabul edilmiş tavizin kaydı:** container non-root çalıştığı için Chromium
  kendi setuid sandbox'ını açamaz ve `--no-sandbox` ile başlatılır. Bu,
  Playwright'ın belgelediği iki seçenekten biridir. Chromium sandbox'ını da
  isteyen kullanıcı, Playwright'ın seccomp profilini `security_opt` ile
  bağlayabilir; `docs/installation.md` bunu anlatır. Telafi edici kontroller:
  non-root kullanıcı, read-only olmayan tek yazılabilir dizin olarak artifact
  volume'ü, internal network, tarayıcı her audit sonunda kapatılır.
- Screenshot **yalnızca viewport** boyutunda alınır (`fullPage: false`).
  Kontrolsüz full-page screenshot yasaktır (bellek/disk DoS yüzeyi).

### 2.7 Artifact erişimi ve path traversal

- Dosyalar `ARTIFACT_ROOT` altında **relative** yolla saklanır; DB'de asla
  mutlak yol tutulmaz.
- Relative yol yalnızca sistem tarafından üretilir:
  `screenshots/<audit_id>/<uuid>.png`.
- Servis, dosyayı açmadan önce `path.resolve(ARTIFACT_ROOT, rel)` sonucunun
  `ARTIFACT_ROOT + path.sep` ile başladığını doğrular; aksi halde 400
  (`PATH_TRAVERSAL`). Symlink'ler `realpath` sonrası tekrar kontrol edilir.
- İstemciye dosya yolu değil **artifact kimliği** verilir; indirme
  `GET /artifacts/{artifact_id}` üzerinden binary olarak yapılır.
- Saklama süresi `ARTIFACT_RETENTION_DAYS` (varsayılan 30). Günlük temizlik
  işi süresi dolmuş dosyaları siler ve kaydı `deleted_at` ile işaretler.

### 2.8 Servis erişimi

- `analyzer` varsayılan olarak host'a port açmaz; yalnızca Docker internal
  network'ten erişilir. Geliştirme için ayrı bir compose profili
  (`--profile dev`) portu açar.
- Tüm uçlar `X-API-Key` ister (`/healthz` hariç).
- Anahtar eksik/yanlış → 401, gövdesiz.

## 4. PostgreSQL şeması

`pitchtrace` şeması, `citext` + `pgcrypto` extension'ları.

### 4.1 İlişki haritası

```
campaigns 1─n companies 1─n contacts
                  ├─1─n audits 1─n audit_pages
                  │        ├─1─n findings
                  │        ├─1─n artifacts
                  │        └─1─1 scores
                  └─1─n email_drafts 1─n draft_claims n─n findings
                                     ├─1─n approvals
                                     └─1─n outreach_log
audit_jobs 1─1 audits        suppression_list (bağımsız)
```

### 4.2 Kampanya ve firma (rev. 2)

```sql
CREATE TABLE campaigns (
  id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  name          text NOT NULL,
  sector        text NOT NULL,
  city          text NOT NULL,
  country       text NOT NULL DEFAULT 'TR',
  language      text NOT NULL DEFAULT 'tr' CHECK (language IN ('tr','en')),
  max_companies int  NOT NULL DEFAULT 50 CHECK (max_companies BETWEEN 1 AND 50),
  page_limit    int  NOT NULL DEFAULT 5  CHECK (page_limit BETWEEN 1 AND 5),
  min_score     int  NOT NULL DEFAULT 70 CHECK (min_score BETWEEN 0 AND 100),
  service_fit   jsonb NOT NULL DEFAULT '{}'::jsonb,
  created_at    timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE companies (
  id                uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  campaign_id       uuid NOT NULL REFERENCES campaigns(id) ON DELETE CASCADE,
  name              text NOT NULL,
  submitted_url     text NOT NULL,   -- kullanıcının verdiği ham değer; ASLA ezilmez
  normalized_domain citext NOT NULL, -- lowercase, www yok, punycode, path/query yok
  resolved_url      text,            -- ilk başarılı audit'in final URL'i
  source            text NOT NULL DEFAULT 'csv' CHECK (source IN ('csv','manual','api')),
  created_at        timestamptz NOT NULL DEFAULT now(),
  CONSTRAINT companies_campaign_domain_unique UNIQUE (campaign_id, normalized_domain)
);
```

`UNIQUE(domain)` global kısıtı **kaldırıldı**: aynı firma farklı kampanyalarda
bulunabilir. Tekilleştirme kampanya içinde yapılır. Kampanyalar arası tekrar
gönderim riski suppression listesi ve `outreach_log` ile yönetilir.

Redirect sonucu yalnızca `audits.final_url` ve `companies.resolved_url`
alanlarına yazılır; `submitted_url` ve `normalized_domain` değişmez.

### 4.3 Audit, sayfa, bulgu, artifact

```sql
CREATE TABLE audits (
  id               uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  company_id       uuid NOT NULL REFERENCES companies(id) ON DELETE CASCADE,
  status           text NOT NULL DEFAULT 'queued'
                   CHECK (status IN ('queued','running','completed','failed')),
  page_limit       int  NOT NULL CHECK (page_limit BETWEEN 1 AND 5),
  entry_url        text NOT NULL,
  final_url        text,
  robots_allowed   boolean,
  pages_planned    int NOT NULL DEFAULT 0,
  pages_fetched    int NOT NULL DEFAULT 0,
  bytes_transferred bigint NOT NULL DEFAULT 0,
  analyzer_version text NOT NULL,
  started_at       timestamptz,
  finished_at      timestamptz,
  error_code       text,
  error_message    text,
  created_at       timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE audit_pages (
  id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  audit_id    uuid NOT NULL REFERENCES audits(id) ON DELETE CASCADE,
  url         text NOT NULL,
  role        text NOT NULL CHECK (role IN ('home','contact','about','sitemap_pick')),
  http_status int,
  final_url   text,
  load_ms     int,
  html_bytes  int,
  fetched_at  timestamptz NOT NULL DEFAULT now(),
  error       text,
  UNIQUE (audit_id, url)
);

CREATE TABLE artifacts (
  id         uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  audit_id   uuid NOT NULL REFERENCES audits(id) ON DELETE CASCADE,
  kind       text NOT NULL CHECK (kind IN ('screenshot','export')),
  rel_path   text NOT NULL,           -- ARTIFACT_ROOT'a göre, asla mutlak
  mime       text NOT NULL,
  bytes      int  NOT NULL,
  sha256     text NOT NULL,
  created_at timestamptz NOT NULL DEFAULT now(),
  deleted_at timestamptz
);

CREATE TABLE findings (
  id           uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  audit_id     uuid NOT NULL REFERENCES audits(id) ON DELETE CASCADE,
  company_id   uuid NOT NULL REFERENCES companies(id) ON DELETE CASCADE,
  code         text NOT NULL,
  category     text NOT NULL CHECK (category IN ('MOBILE','TECH','PERF','SEO','CONV','CONTACT','INF')),
  severity     text NOT NULL CHECK (severity IN ('low','medium','high')),
  confidence   text NOT NULL CHECK (confidence IN ('observed','inferred','manual')),
  url          text,
  evidence     jsonb NOT NULL DEFAULT '{}'::jsonb,
  metric_name  text,
  metric_value numeric,
  metric_unit  text,
  artifact_id  uuid REFERENCES artifacts(id) ON DELETE SET NULL,
  observed_at  timestamptz NOT NULL DEFAULT now(),
  UNIQUE (audit_id, code, url)
);
```

### 4.4 Kuyruk

```sql
CREATE TABLE audit_jobs (
  id           bigserial PRIMARY KEY,
  audit_id     uuid NOT NULL UNIQUE REFERENCES audits(id) ON DELETE CASCADE,
  company_id   uuid NOT NULL REFERENCES companies(id) ON DELETE CASCADE,
  status       text NOT NULL DEFAULT 'queued'
               CHECK (status IN ('queued','running','completed','failed')),
  attempts     int NOT NULL DEFAULT 0,
  max_attempts int NOT NULL DEFAULT 2,
  run_after    timestamptz NOT NULL DEFAULT now(),
  locked_at    timestamptz,
  locked_by    text,
  last_error   text,
  created_at   timestamptz NOT NULL DEFAULT now()
);
```

Claim sorgusu:

```sql
UPDATE pitchtrace.audit_jobs j
   SET status='running', attempts=attempts+1, locked_at=now(), locked_by=$1
 WHERE j.id = (SELECT id FROM pitchtrace.audit_jobs
                WHERE status='queued' AND run_after <= now()
                ORDER BY created_at
                FOR UPDATE SKIP LOCKED LIMIT 1)
RETURNING j.*;
```

Stale lock: `status='running' AND locked_at < now() - interval '10 minutes'`
→ `queued`. `attempts >= max_attempts` → `failed` + audit `failed`.

### 4.5 Taslak, onay, sonuç, suppression

`email_drafts`, `draft_claims`, `draft_claim_findings`, `approvals` rev. 1 ile
aynıdır. `outreach_log.status` enum'u değişti:

```sql
CREATE TABLE outreach_log (
  id         uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  draft_id   uuid NOT NULL REFERENCES email_drafts(id) ON DELETE CASCADE,
  company_id uuid NOT NULL REFERENCES companies(id) ON DELETE CASCADE,
  channel    text NOT NULL DEFAULT 'manual_email',
  status     text NOT NULL CHECK (status IN
               ('exported','sent','replied','no_reply','bounced','opted_out')),
  marked_by  text NOT NULL,
  note       text,
  marked_at  timestamptz NOT NULL DEFAULT now()
);
```

`rejected` durumu kaldırıldı; anlam ikiye ayrıldı:
- **`opted_out`** — alıcı iletişim istemiyor (`outreach_log`).
- **`rejected_by_human`** — taslak insan tarafından reddedildi (`email_drafts.status`).

## 5. Suppression kuralları (rev. 2)

| Olay | Otomatik davranış |
|---|---|
| `sent` | Suppression **eklenmez** |
| `replied` | Suppression **eklenmez** (olumlu yanıt da `replied`'dır) |
| `no_reply` | Suppression **eklenmez** |
| `bounced` | **Yalnızca ilgili e-posta** adresi suppression'a eklenir |
| `opted_out` | **Yalnızca ilgili e-posta** adresi suppression'a eklenir |
| domain suppression | Yalnızca **açık insan kararıyla** (`POST /suppression {scope:"domain"}`) |

Rev. 1'deki "`replied` → domain suppression" kuralı kaldırıldı; ilgilenen bir
firmayı kalıcı olarak engelliyordu.

Suppression **üç noktada** kontrol edilir:
1. Firma import edilirken (domain scope) — import raporunda `suppressed` sayılır.
2. `GET /drafts/context` çağrısında (email + domain) — 409.
3. `GET /drafts/{id}/export` çağrısında tekrar (email + domain) — 409.

Üçüncü kontrol zorunludur: onay ile dışa aktarım arasında günler geçebilir.

## 6. Analyzer API kontratları

Base `http://analyzer:8080` · Auth `X-API-Key` (`/healthz` hariç).

### 6.1 Kampanya ve firma

```
POST /campaigns                              → 201 {id, …}
GET  /campaigns/{id}                         → 200 {…, stats}
POST /campaigns/{id}/companies               → 201 {company_id, normalized_domain}
POST /campaigns/{id}/companies:import        → 200 {imported, deduped, suppressed, rejected[]}
GET  /campaigns/{id}/companies?filter=…      → 200 {items[]}
```

### 6.2 Audit — kampanya seviyesinde orkestrasyon (rev. 2)

Firma başına bağımsız uzun polling **kullanılmaz**. 50 firma × concurrency 2 ×
90 sn ≈ 37,5 dakika sürebilir; firma başına polling bütçesi kuyruktaki son
işler başlamadan tükenir.

```
POST /campaigns/{id}/audits
  body: {only_missing?: boolean = true, page_limit?: int}
  → 202 {campaign_id, enqueued, skipped_existing, skipped_suppressed}

GET  /campaigns/{id}/audit-progress
  → 200 {
      "campaign_id": "...",
      "total": 50, "queued": 20, "running": 2,
      "completed": 25, "failed": 3,
      "finished": false,
      "oldest_queued_age_s": 412,
      "estimated_remaining_s": 990
    }
```

`finished = (queued == 0 && running == 0)`.

Tek firma için mevcut uçlar korunur:

```
POST /audits {company_id, page_limit?}   → 202 {audit_id, status:"queued"}
                                         → 200 {audit_id, status:"running"}  (idempotent)
GET  /audits/{audit_id}                  → 200 {status, progress, error, findings_count, …}
GET  /audits/{audit_id}/findings         → 200 {items[]}
POST /audits/{audit_id}/score            → 200 {total, breakdown, rule_version}
```

Hata kodları: `SCHEME_BLOCKED`, `CREDENTIALS_IN_URL`, `PRIVATE_ADDRESS`,
`HOSTNAME_BLOCKED`, `DNS_FAILURE`, `TOO_MANY_REDIRECTS`, `ROBOTS_DISALLOWED`,
`ROBOTS_FETCH_FAILED`, `TLS_FAILURE`, `HTTP_ERROR`, `TIMEOUT`,
`RESPONSE_TOO_LARGE`, `RENDER_CRASH`, `SHUTDOWN`.

### 6.3 Artifact

```
GET /artifacts/{artifact_id}
  → 200 binary (image/png), Content-Disposition: inline
  → 400 {error:"PATH_TRAVERSAL"}
  → 404 {error:"ARTIFACT_GONE"}     # retention sonrası silinmiş
```

n8n, screenshot'ı bu uçtan **binary** olarak alır ve inceleme formunda
finding özeti ile birlikte gösterir. Tarayıcıya filesystem yolu verilmez,

## 7. Finding kataloğu (rev. 2)

Her kodun kataloğa üç alanı eklendi:

- `status`: `stable` | `experimental`
- `outreach_eligible`: yalnızca `stable` kodlar `true` olabilir.
- **`scope`: `page` | `site`** (F4'te eklendi)

**Kapsam kuralı (normatif).** `page` kapsamlı bulgular her taranan sayfa için
ayrı değerlendirilir ve o sayfanın URL'ine bağlanır. `site` kapsamlı bulgular
taranan **tüm** sayfaların toplamı üzerinden bir kez üretilir ve ana sayfanın
son adresine bağlanır. "İletişim formu yok" gibi YOKLUK bulguları zorunlu
olarak site kapsamlıdır: tek bir sayfada bulunmaması sitede bulunmadığı
anlamına gelmez. Buna göre CONV_*, CONTACT_*, TECH_NO_HTTPS, TECH_TLS_* ve
INF_* site; MOBILE_*, SEO_* ve kalan TECH_* sayfa kapsamlıdır.

Site kapsamlı bulgular tek bir sayfaya ait olmadığı için `artifact_id`
taşımazlar (screenshot yalnızca sayfa bulgularına bağlanır).

Kod listesinin tek doğruluk kaynağı `src/findings/catalog.ts`'tir;
`docs/finding-codes.md` bu dosyadan üretilir ve güncelliği testle doğrulanır.

**Yalnızca `outreach_eligible` bulgular e-posta taslağında kullanılabilir**
(validator V16). `experimental` bulgular kaydedilir, skorda ağırlığı düşüktür
veya sıfırdır, ve insana gösterilir — ama iddia üretemez.

## 8. AI structured-output şeması

Model **gövde metni üretmez**; yalnızca claim listesi üretir. Gövde sunucuda
`render.ts` ile derlenir; böylece doğrulanmamış serbest metin yapısal olarak
kaçamaz.

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "title": "OutreachDraftOutput",
  "type": "object",
  "additionalProperties": false,
  "required": ["language","subject","greeting","claims","closing"],
  "properties": {
    "language": { "enum": ["tr","en"] },
    "subject":  { "type": "string", "minLength": 10, "maxLength": 90 },
    "greeting": { "type": "string", "maxLength": 120 },
    "claims": {
      "type": "array", "minItems": 2, "maxItems": 6,
      "items": {
        "type": "object", "additionalProperties": false,
        "required": ["text","claim_type","confidence","finding_ids"],
        "properties": {
          "text":        { "type": "string", "minLength": 15, "maxLength": 320 },
          "claim_type":  { "enum": ["assertion","question","neutral"] },
          "confidence":  { "enum": ["observed","inferred"] },
          "finding_ids": { "type": "array", "maxItems": 3,
                           "items": { "type": "string", "format": "uuid" } }
        }
      }
    },
    "closing": { "type": "string", "maxLength": 240 }
  }
}
```

## 10. n8n workflow sınırları

**n8n yapar:** tetikleme, sıralama, polling, hata dallanması, LLM çağrısı,
insan onay formu, CSV okuma/eşleme.

**n8n yapmaz:** site gezme, HTML parse, puan hesaplama, taslak doğrulama,
suppression kararı, doğrudan Postgres yazma (tüm yazmalar API'den), Function
node içinde iş kuralı (yalnızca alan eşlemesi, ≤20 satır).

| # | Dosya | Girdi → Çıktı | Durma koşulu |
|---|---|---|---|
| 01 | `01-import-leads.json` | CSV → `companies:import` | >50 satır → hata |
| 02 | `02-run-audits.json` | `POST /campaigns/{id}/audits` → **30 sn'de bir `GET /audit-progress`**, `finished:true` olana kadar, maks **120 iterasyon (60 dk)** | Bütçe dolarsa rapor + durur; kuyruk DB'de kalır |
| 03 | `03-generate-drafts.json` | `/drafts/context` → LLM → `POST /drafts` | 409/412 → firma atlanır |
| 04 | `04-review-and-export.json` | Form + `GET /artifacts/{id}` (binary) → `POST /approval` → `GET /export?format=eml` | Export'ta 409 suppression → dosya yok |
| 05 | `05-mark-outcome.json` | `POST /outreach` | — |

dakikalık en kötü durumun üzerine ~%60 pay bırakır.

## 11. Geliştirme sırası

### VS — Dikey dilim (ilk implementasyon, F0–F9'dan önce) — **TAMAMLANDI**

En riskli parçayı uçtan uca doğrular: SSRF güvenliği + kuyruk + gerçek tarayıcı.

Kapsam: Postgres + minimum migration; minimal Fastify; tek kampanya/tek firma;
audit'i kuyruğa alma; tek process içinde en fazla iki worker loop; SSRF
kontrolü; `robots.txt` kontrolü; **yalnızca ana sayfa** Playwright ile;
375×812 screenshot; üç finding (`MOB_NO_VIEWPORT`, `MOB_HORIZONTAL_OVERFLOW`,
`SEO_MISSING_TITLE`); finding'leri DB'ye yazma; `GET /audits/{id}` ile sonuç.

Kapsam dışı: n8n workflow'ları, LLM, prompt, validator, scoring, taslak, `.eml`,
approval formu, contact discovery, PSI, 5 sayfalık crawler, dashboard, gönderim.

**Kabul kriterleri:**
- `docker compose up` ile postgres + analyzer ayağa kalkıyor.
- Analyzer host'a varsayılan olarak açılmıyor; `--profile dev` ayrı tanımlı.
- Kurgusal firma oluşturulabiliyor.
- `POST /audits` → `202 + audit_id`.
- Bir iş yalnızca bir kez claim ediliyor (eşzamanlı claim testi).
- Aynı anda en fazla iki audit çalışıyor (örnekleme ile doğrulanıyor).
- Private/reserved IP hedefleri reddediliyor.
- Redirect ile private IP'ye geçiş engelleniyor.
- `robots.txt: Disallow: /` → hiçbir sayfa açılmıyor (fixture sunucusunda
  istek sayacı 0).
- Güvenli fixture sayfası Playwright ile açılıyor, mobil screenshot üretiliyor.
- Üç finding için pozitif **ve** negatif fixture testi var.
- Finding'lerde audit, company, URL, evidence, `observed_at` dolu.
- Worker hatası → audit kontrollü `failed`.
- Testler internet bağlantısı olmadan yerel fixture sunucusunda çalışıyor.
- README yalnızca çalışan özellikleri anlatıyor.

## 11.1 Fırsat puanlama — `scoring.v1` (F6'da uygulandı)

Puan saf bir fonksiyondur: `(bulgu kodları, kampanya service_fit) → puan`.
Aynı girdi her zaman aynı sonucu verir ve `rule_version` ile kaydedilir.

**Bileşenler ve tavanlar** (toplam 100):

| Bileşen | Tavan | Kaynak kategoriler |
|---|---|---|
| `technical` | 25 | TECH, PERF, **SEO** |
| `mobile` | 20 | MOBILE |
| `conversion` | 20 | CONV, INF |
| `service_fit` | 20 | Kampanyanın `service_fit` ağırlıkları |
| `contact` | 15 | CONTACT (ulaşılabilirlik) |

SEO eksikleri ayrı bir kova almaz; bulunabilirlik problemi olarak `technical`
içine yazılır.

**Puanlama kuralları:**

1. **Tekilleştirme.** Bir kod kaç sayfada görülürse görülsün **bir kez**
   sayılır. Aksi halde beş sayfalık bir crawl, tek sayfalık bir siteye göre
   aynı sorunu beş kat ağır puanlardı.
2. **Önem puanları:** `high = 8`, `medium = 5`, `low = 2`. Bileşen kendi
   tavanında kırpılır.
3. **`experimental` kodlar puana katkı vermez.** Outreach'te iddia olarak
   kullanılamayan bir bulgu, e-posta yazıp yazmama kararını veren puanı da
   yükseltmemelidir (şu an: `PERF_CLS_HIGH`).
4. **`inferred` bulgular puana katkı vermez.** Türetildikleri gözlemler zaten
   sayılır; saymak aynı problemi iki kez puanlamak olur
   (`INF_NO_ONLINE_APPOINTMENT` ← `CONV_NO_BOOKING_LINK` + `CONV_NO_CONTACT_FORM`).
5. **İletişim bileşeni ulaşılabilirliktir**, problem sayısı değil:
   `CONTACT_ROLE_EMAIL_FOUND` varsa 15, yoksa 0.
6. **İletişimsiz tavan.** Kurumsal adres yoksa toplam `NO_CONTACT_TOTAL_CAP`
   (49) değerini aşamaz — gönderilecek bir yer yoksa fırsat eyleme dönüşemez.
   Bu, varsayılan 70 eşiğinin altında kalmayı garanti eder. Tavan,
   `breakdown.no_contact_penalty` (≤ 0) olarak yazılır; böylece
   **bileşenlerin toplamı her zaman `total`'a eşittir**.
7. **`service_fit`** yalnızca *mevcut ve sayılan* kodlara uygulanır; kod başına
   ve toplamda 20 ile sınırlıdır. Boş bırakılırsa 0 katkı verir — pilot öncesi
   doldurulması gerekir.

`details` alanı puanın nasıl oluştuğunu insana açıklar: sayılan kodlar,
dışlananlar ve gerekçeleri, `service_fit` eşleşmeleri.

**Eşik kalibrasyonu:** `min_score = 70` hâlâ kalibre edilmemiş bir tahmindir.
Pilot sonrası `rule_version` artırılarak yeniden değerlendirilecektir.
